Surface card — the status strip

The strip under a surface card currently prints the raw ledger event name and a ledger coordinate. Three options for what it should say instead, each shown in both states that matter: while the view is being built, and once it has settled.

Today

What ships now

The strip is fed by projectStatusLine, which builds one string for every state: event_type · connector.op · ledgerId.

Compared

Option Says something new Cost
A — quiet No, by design — nothing new was there ~40 lines deleted; strip becomes two states
B — freshness Yes, but a third clock on one card Needs a relative-time source the strip lacks
C — provenance Yes — inferred vs curated is invisible today Needs basis plumbed to the strip; it rides view.derived already

Recommendation — A now, C next

A is a deletion and can ship immediately: it removes the jargon, the two unreadable coordinates and a whole line of chrome, and loses nothing a person could read.

C is the only option that adds real information, and the data is already on the wire — view.derived carries the basis (built-in, learned, shape-matched, inferred). But it is a product decision about whether users should see how a layout was chosen, so it wants its own call rather than riding a cleanup.

Either way the ledger ids leave the card face. If they are worth keeping for support, they belong on a copy affordance or the events view — not printed twice on a card someone is reading.
