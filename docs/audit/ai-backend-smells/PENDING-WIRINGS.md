# ai-backend — pending-wiring ledger

The debt this repo had no name for. A module lands, its wiring does not, and
nothing records the gap — so ten modules sat invisible for up to 2.5 months, not
because anyone abandoned them but because "built, not yet wired" is a state the
tree could not represent ([HANDOFF.md](../../plan/ai-backend-consolidation/HANDOFF.md)
§4–5). This is that record.

It is the companion to the ratchet: [`orphan_ratchet_baseline.txt`](../../../services/ai-backend/tests/unit/orphan_ratchet_baseline.txt)
is the machine-checked set (grow it and CI fails); this file is the **why** for
each entry, and it is what turns a scanner hit into a decision.

**It supersedes [DELETE-REPLACE.md](DELETE-REPLACE.md) §B.** That section proposed
deleting ~8,600 LOC of "unreachable code" across 10 modules. Reading all 23 current
orphans against source says the genuinely-safe-to-delete-now set is **~45 LOC, and
possibly zero without an author's sign-off** — every other entry is blocked on named
work, ready to wire, or not actually an orphan.

Generated by reading each module's source + docstring + `git log` (5 parallel
readers, 2026-08-01). "Run it, don't read it": three claims in the audit and the
execution plan did not survive contact with the source — see §Corrections.

---

## Disposition — the four states an "orphan" can be in

| State             | Meaning                                                                                      | Count |
| ----------------- | -------------------------------------------------------------------------------------------- | ----: |
| **Blocked**       | Names a specific **unshipped** dependency (route, hook, consumer, column). Cannot wire yet.  |    13 |
| **Wireable**      | No unshipped blocker — every dep is present; the decision is **wire-or-drop**, not a wait.   |     5 |
| **Delete**        | No blocker **and** superseded by a wired twin / stale shim / redundant scaffolding.          |     3 |
| **Not an orphan** | Live `python -m` entrypoint (`__main__` guard) the scanner mis-flags. Exclude from the scan. |     2 |

**The rule that governs deletion** (adopted in [TASKS.md](../../plan/ai-backend-consolidation/TASKS.md)):
nothing **younger than 30 days** is deleted without asking its author. As of
2026-08-01, **12 of the 23 are <30 days** (added after 2026-07-02) — so most of even
the Delete/Wireable set is "confirm first," not "remove now."

## Wireable now — no unshipped blocker; decide wire-or-drop (5)

Every dependency is present; these are landed _behind_ their switch. Each is either
a scheduled wiring or a candidate to drop — none is a "wait."

- **`agent_runtime.capabilities.concurrency.provider_hints`** (332, 07-29) — states no
  blocker, but its insertion point is demonstrably there: `batch_concurrency_composition.py`
  builds a bare `DeclaredConcurrencyPolicySource` feeding only `PRODUCT_CATALOG` — the exact
  gap it closes by adding the MCP `readOnlyHint`/`destructiveHint`/`idempotentHint` tier.
  Fails safe (narrow-only). **This is [TASKS.md](../../plan/ai-backend-consolidation/TASKS.md)
  T1.3's lever, not a deletion.** → **wire.**
- **`runtime_worker.jobs.approval_expiry_sweeper`** (245, 05-05) — the only thing that
  expires stale approvals. All port methods + a production `HttpWorkspaceMembershipResolver`
  are shipped; it is just never constructed in `runtime_worker/__main__.py` (gated behind
  `RUNTIME_APPROVAL_EXPIRY_SWEEP_ENABLED`, off). **This is TASKS.md T2.3.** → **wire** (also
  construct a membership resolver in the worker `__main__`).
- **`runtime_worker.jobs.todo_recurrence_materializer`** (481, 05-18) — the backend endpoint
  `/internal/v1/todos/series/materialize-due` and its schema are **live**; the only gap is
  starting the loop in the worker `__main__` (flag `RECURRENCE_MATERIALIZER_ENABLED`, off).
  → **wire-or-drop** (unlike its feature-sibling `todo_extractor`, nothing unshipped blocks it).
- **`runtime_worker.jobs.encrypt_existing_columns`** (216, 05-04) — operator one-shot
  re-encryption backfill; its precondition (`RUNTIME_FIELD_ENCRYPTION=envelope_v1`) is live.
  Same shape as the wired `RetentionBackfillJob`. → **wire-or-drop, gated on the open
  question** "has the backfill already run everywhere?" (HANDOFF §6a / TASKS T1.2).
- **`agent_runtime.release.e2_final_conformance`** (524, 07-26) — a fail-closed release
  conformance report that reads source trees; nothing runs it yet. Names no blocker, but it
  is the aggregator the other conformance gates would report into. **<30 days → confirm with
  author** before treating as delete; likelier a wire (a CI/release step). → **wire-or-hold.**

## Delete candidates — no blocker, superseded/stale/redundant (3)

The only entries where absence costs nothing, because a wired path already does the job.

- **`agent_runtime.effects.reconciliation`** (95, 07-25) — superseded. A parallel,
  **wired** reconciliation lane (`runtime_worker/jobs/repair_execution.py`,
  `runtime_worker/handlers/effect_reconcile.py`, `EffectCoordinator.reconcile`) re-declares
  the same `EffectReconcileQueuePort` name with a different signature. Names nothing it awaits.
  <30 days → **ask author, then delete.**
- **`runtime_worker.legacy_mcp_effect_executor`** (22, 07-25) — a compat shim re-exporting
  the live `mcp_effect_executor` under `Legacy*` names "to preserve already-landed A5 imports."
  That reason is **stale**: no `src` import uses the `Legacy*` aliases (only a shim-guard test).
  <30 days → **ask author, then delete.**
- **`runtime_adapters.in_memory.share_snapshot_store`** (45, 05-06) — redundant test
  scaffolding. Production supplies `ShareSnapshotPort` via `ShareService` itself; a separate
  `InMemoryShareStore` covers the in-memory case. Nothing in `src` instantiates this one.
  **Aged (>30 days) → the single clean delete-now.**

**Bottom line on deletion:** ~45 LOC removable today (`share_snapshot_store`); ~117 more
(`effects.reconciliation` + `legacy_mcp_effect_executor`) once their <30-day authors confirm;
+216 (`encrypt_existing_columns`) if the backfill is confirmed complete. The audit's ~8,600
and the plan's ~1,400 were both high; **"possibly zero" was the honest number.**

## Not an orphan — live entrypoints the scanner mis-flags (2)

Both have `if __name__ == "__main__"` guards and are invoked via `python -m`. The
scanner ([`orphans.py`](../../../tools/ai-backend-smells/orphans.py)) excludes entry
points by **leaf name** (`__main__`, `app`, …) and does not look for a `__main__`
_guard inside the file_, so these read as unreachable when they are not.

- **`runtime_adapters.migrate`** (252, 07-18) — the **live** offline→file-store migration
  CLI. The desktop supervisor spawns `python -m runtime_adapters.migrate --on-boot`
  (`apps/desktop/main/services/migration-runner.ts:66`); it is the sole implementation, with
  an operator runbook. **Not deletable.**
- **`runtime_worker.local_release_control_cli`** (560, 07-27) — the dev/dogfood
  release-control CLI; its server router is mounted at `runtime_api/app.py:491`.
  [FINDINGS.md](FINDINGS.md) §L85 already flagged it as "a genuine CLI, correctly excluded."
  **Not deletable.**

**Recommended scanner fix (own change, not T1.1):** teach `orphans.py` to skip any
module whose source contains an `if __name__ == "__main__":` guard, then prune these two
from `orphan_ratchet_baseline.txt` (the grow-only ratchet tolerates the stale lines until then).

## Ownership

Git first-commit author is the provenance signal, not the semantic owner: the
2026-05 modules are `parthpahwa1`'s; the 2026-07 modules were landed by the
automation account `0x-copilot-dev` on behalf of a program. The **actionable owner
is the PRD / step named in "waits on"** — P3-A1 and P5-A1 (todos/routines), C1
(workspace overlay), Step 15 (promotion/release), PRD-FS-04 (retention),
F6.1 (provider hints), team-memory-cmdk §9 (proposals). Ask there before deleting a
<30-day module, and wire there when the blocker ships.

## Method

`git -C <worktree> log --diff-filter=A` for provenance; the module docstring + a
`grep` of `services/ai-backend/src` for each named blocker to confirm it is truly
absent (and to catch same-name collisions — `promotion`, `retention`, and
`reconciliation` each have a wired same-named sibling that inflates the scanner's
mention count). Every "waits on" is quoted from source, not paraphrased.
