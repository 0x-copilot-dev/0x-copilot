# Pre-existing CSS selector shadowing — the burn-down list for
# tools/check_css_selector_shadowing.py.
#
# Every line is an `apps/*` selector that a `packages/*` stylesheet already owns.
# These predate the gate; they are DEBT, not approval. There is deliberately no
# `--update-baseline` writer: the only sanctioned way to land new shadowing is a
# `/* shadow-ok: <reason> */` comment on the offending rule, which shows up in
# the diff. Removing an app-side copy makes its line here stale, and a stale
# line FAILS the gate — so this file can only ever shrink.
#
# Format: <repo-relative app stylesheet> :: <normalised selector>
#
# The whole of the block below is one defect: apps/frontend/src/styles.css
# carries a private fork of rules that packages/chat-surface owns. Some of those
# package sheets the web app does import (workspace.css, onboarding.css) — there
# the two copies race on load order. composer.css it does NOT import, so the fork
# is currently the only copy the web app sees, and the day someone adds the
# import (matching apps/desktop/renderer/bootstrap.tsx) the fork starts silently
# winning or losing. Fix by deleting the fork and importing the package sheet.
